# Hybrid 与 DX 协同解码架构

Hybrid 与 DX 只编排原版 WSJT-X / JTDX 的已有能力。`lib_wsjtx/` 和
`lib_jtdx/` 的源码、阈值、候选顺序、AP 调度和数学计算不为协同模式修改；
不通过复制后修改内核绕过这项原则。纯 WSJT-X / JTDX 配置保持独立语义。

本软件仅监听。结果通常以下一时隙开始后 2–3 秒显示为目标；单条回调时间与
全部后台任务结束时间分别评价。不可中断的原版调用不具有强制超时保证。

## 共享边界

```text
不可变音频与时隙时间戳
  -> 各模式的基础原版会话
  -> 观测、角色解析与用途资格
  -> 有界的隔离恢复任务
  -> 共享输出账本
  -> 各模式按规则提交跨时隙状态
```

共享组件位于 `src/decode/cooperative/`：

| 组件 | 职责 |
|---|---|
| `message.rs` | 解析发送方、接收方、网格、CQ 修饰词和 FH 显示结构，保留未解析哈希 |
| `ledger.rs` | 信号匹配、首次输出、来源集合与稳定返回顺序 |
| `recovery.rs` | 校验既有音调及波形支持，在独立输入副本上调用已有消除入口 |

Hybrid 与 DX 各自保留任务选择和台站状态策略。每个原版会话独占哈希本、AP
及奇偶记忆、工作空间和残差，不跨 worker 共享这些私有状态。基础会话不接收
恢复结果的倒灌，也不接受长期跨解码器哈希注入；现有导入接口无法撤销旧映射。

## 观测与输出

可显示不等于可作为恢复种子。原版没有提供的来源信息保留 Unknown，不把
常规调用路径等同于无先验解码。恢复消息不能成为新的独立证据或继续消除。

输出账本分开保存来源集合与首次输出状态。同源重复不会升级成 Both，后来
增加支持来源也不会重复回调。带未解析哈希的身份不靠文本或短 hash 与已解析
呼号直接合并；仅在原版完整 79 音调载荷相同、其余字段一致且频率/DT 匹配时，
将 hash 显示展开视为同一编码消息。未知 hash 占位符在完整载荷不同时，即使文本
相同也保留；完全已解析的消息沿用原有文本归一化去重，已解析呼号冲突仍保留。
原版证据与置信度独立记录，不共享 hash 表或反向补写身份。
GUI 的 `?`、`sic`、`ctx` 分别表示未知来源、交叉消除恢复和上下文恢复。

## Hybrid

长期 WSJT-X、JTDX/noAGC 与 JTDX/AGC 三条基础会话独立运行，基础并集始终保留。
两条 JTDX 路径默认各一个逻辑分区；显式传入 `jtdx_threads=0` 才启用原版按 CPU
选择分区的自动模式。SWL 开关统一控制两条 JTDX 路径。N41 / N47 沿用既有
WSJT-X 阶段，N50 并发处理 WSJT-X 收尾及两条 JTDX 的完整输入。

AGC 路径只补充输出，不参与已有 WSJT-X 与 noAGC 路径之间的消除种子选择，也
不倒灌原版状态。证据保留 `jtdx-agc` 变体来源，但来源集合与独立确认按 JTDX
家族归并；两条 JTDX 路径一致不构成跨算法独立确认。

一轮交叉消除每方向最多三个种子，每方向至多一次。种子必须具有原版输出的
有效音调、可解释的发送方、有限且在带内的频率和 DT；缺失音调不靠文本补造。
重编码只核对现有音调。原始输入中的数据符号波形支持比例至少 0.70；消除结果
若非有限或能量增加超过 1% 则回退。JTDX 方向还要求原版明确 Regular。
WSJT-X 未暴露内部 AP 类型，保持 Unknown，并使用独立的波形用途门槛。

额外任务复制原始音频、调用已有消除函数，再创建隔离的原版会话。恢复结果
只作终端输出。CLI `--no-hybrid-sic` 或 GUI Cross cancellation 可以关闭这条
增强通道，基础两个会话不受影响。

实时模式在源 worker 完成后，按已收到的对侧结果选择机会；N50 处理三秒后不再
启动新的 Hybrid 恢复。文件模式等待基础结果完整后选种子，并按固定方向提交。
二者提交点不同，不承诺所有录音上的新增集合相同。任务产生消息后及时回调，
不等待所有 worker 完成才显示。

被动 QSO 提示按当槽证据重建，不保留永不过期的历史高分提示。泛化逐呼号对
重放、AP callbook 导入、SameParityA7 自动反馈和全带前缀预览均未默认启用。

## DX

每槽先过期旧观测，再冻结目标快照。长期 JTDX SWL 监听与窄带恢复并行，所有
状态在本槽任务结束后按稳定顺序提交。最多五个焦点、四个恢复执行线程；每个
额外任务持有独立原版会话。`jtdx_threads` 是原版逻辑分区参数，不等于这些执行线程。

用户提供呼号对但没有焦点时，可运行标准 WSJT-X 上下文冷启动，保持
`nagain=false`；连续失败两次后空一槽。已有焦点因奇偶条件跳过时不触发冷启动。

用户网格与固定频率独立于观测，热更新后重新应用新用户值，固定频率可替换和
清空。RR73 不作为网格；硬冲突行在采集前被排除。明确 Regular 的目标发送记录
才能建立强网格与奇偶，恢复只产生四槽有效期的弱频率线索。原生频率与奇偶保留
十六槽，观测网格在六十四个无目标活动槽后过期。奇偶冲突先解除旧锁，再等待
不同槽确认。相同可信度的频率观测可以更新频漂和最近性。

FH 外推要求同槽、原生目标发送方观测符合 60 Hz 间隔；真实焦点先于预测点。
用户 pin、跨槽观测和派生线索不能制造多流格点。

## 配置、预算与验证

原版调用开始后不可强制取消。Hybrid 的三秒开工门槛和 DX watchdog 只控制后续
任务启动；仍需监控收尾时间与下一槽排队。回调错误会返回，并回收已启动任务。

本项目的单元测试直接在本机运行，使用 `--profile fast` 或 `--release`。比较灵敏度
时保持输入、配置、CallDB 和构建条件一致，逐条保留旧信号；新增不能抵消丢失。
CSV 未标注消息不直接计作已确认增益。

JTDX 的 430/431 长录音校准固定为四个逻辑分区、2022 CallDB、200–3000 Hz、
SWL / AGC 关闭且无用户 QSO 上下文。生产默认一个分区；显式自动模式需要记录
可见核心数和实际分区，不能把 `threads=0` 当作跨机器固定操作点。测试门槛不降低。

具体运行规则见 [Hybrid](HYBRID.md)、[DX](DX.md) 和 [JTDX](JTDX.md)。
