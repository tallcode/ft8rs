About

ft8.rs is an FT8 decoder based on WSJT-X and JTDX, reimplemented in Rust with additional experimental decoding features developed for this project.

For developers, ft8rs is the Rust FT8 decoding library used by the ft8.rs application.

Listen to activity across the band or follow a particular callsign. The five decoding modes are WSJT-X, WSJT-X+, JTDX, Hybrid and DX.

Design philosophy

We put decoding sensitivity first. ft8.rs uses available CPU power to search received audio more thoroughly and recover as many weak-signal FT8 messages as possible. Deeper searches take more processing power and time, so we designed ft8.rs for receive-only operation on computers with ample CPU capacity. Small devices with limited processing power are outside the supported scope.

  • WSJT-X and JTDX are Rust ports of the original FT8 receive decoders, preserving each decoder's search and decoding behavior.
  • WSJT-X+ extends the WSJT-X decoder with a broader candidate search and retries to recover more weak-signal messages.
  • Hybrid runs one WSJT-X+ path and two JTDX paths in parallel. It combines their strengths to find more messages and uses substantially more CPU than a single decoder path.

About FT8

FT8 is an amateur-radio digital mode for weak-signal communication. It uses 15-second transmit/receive slots and short, structured messages to exchange callsigns, grid locators, signal reports and contact acknowledgements. It is intended for basic exchanges rather than voice or long conversations. See the official WSJT-X User Guide for background.

Sensitivity comparison

Both tests use the ft8.rs GUI profile defaults. AP is on and SWL is off in all five modes. WSJT-X+ and both Hybrid modes use compatibility recovery (Pc) and candidate retry (Pr). Both Hybrid modes use cross cancellation, and Hybrid + exp also enables the experimental decoder.

Synthetic data test

We replayed the same 144 FT8 recordings with the five decoder configurations shown below. They cover stable weak signals and selected interference conditions, with known target messages, frequencies and timing.

Each recording combines a generated FT8 waveform (produced by an implementation based on WSJT-X's gen_ft8wave.f90) with synthetic noise, a continuous tone, or overlapping signals. The generator chooses target callsigns and grids independently. The original message, frequency and timing provide the reference for scoring. Another 48 recordings without target messages check for false decodes. The chart counts the 144 known targets. No incorrect messages were observed from any mode across these 192 recordings.

These conditions were deliberately chosen for the experiment. In everyday reception, weak signals often face changing fading, drift and interference; they are rarely this stable or controlled. The increase shown here cannot be used to predict real-world decode rates, and it does not mean every receive slot will yield more messages.

Getting started

These steps are for the Windows graphical app.

  1. Connect your audio. Tune your radio or SDR to the FT8 frequency you want to receive. Route its audio to your computer using a soundcard, USB audio or a virtual audio cable. Keep your computer's clock accurate.
  2. Open the app. Extract the entire ZIP archive and run ft8rs.exe.
  3. Select the input. In Settings → Audio, choose your receiver's input device and channel. Check that an audio level is shown. If the signal is present on only one channel, choose Left or Right as appropriate.
  4. Choose a mode. Start with the default WSJT-X mode. You can try other modes in Settings → Decode.
  5. Start listening. Click the play button in the main window. FT8 reception follows 15-second slots; decoded messages appear as they become available after each slot. Click stop to finish.

My callsign and grid

For general band listening, you can leave these fields blank. In the My Station section of Settings → General, enter your own callsign and grid locator in Callsign and Grid. The main window's Callsign / Grid fields specify the target station.

Entering your own callsign can help decode some weak messages containing that callsign and resolve its hashed representations. The message list also highlights your callsign.

Entering a callsign does not enable transmission; ft8.rs remains receive-only.

Decoding modes

Select a mode in Settings → Decode → Profile or use the Profile menu.

WSJT-X
The default mode uses WSJT-X FT8 decoding. It is suitable for getting started and general band monitoring.
WSJT-X+
Displays the WSJT-X baseline results first, then automatically runs compatibility recovery and candidate retry. Compatibility recovery (Pc) looks for legacy RR73 and some CQ messages missed during candidate selection. Candidate retry (Pr) tries other time and frequency alignments for some weak or overlapping signals.
JTDX
Uses JTDX FT8 decoding and may find different messages from WSJT-X on the same audio.
  • SWL is off by default. Enable it in Settings → Decode to use JTDX's listening-oriented search. It affects both JTDX paths in Hybrid. It may take longer and may miss some messages found with it off.
Hybrid
Runs one WSJT-X+ path and two JTDX paths, then merges their results and removes duplicates. The primary WSJT-X+ path automatically uses compatibility recovery (Pc) and candidate retry (Pr), including the weak CQ search. The JTDX paths use the original audio and audio with automatic gain adjustment. Running these paths together uses more computing resources. Hybrid automatically runs cross cancellation (SIC): it cancels an already decoded signal from a copy of the audio, then searches for messages that signal may have masked.
  • Experimental decoder: Off by default. Enable Exp. decoder in Settings → Decode to use the Hybrid + exp benchmark mode. It tries to recover stable weak signals and messages affected by single-tone interference or overlapping FT8 signals. Baseline results appear first. Additional results may appear several seconds later. Background work for the slot may take around 10 seconds or longer.
DX
Use DX for a deeper search near a target station's RX audio frequency. Enter the target in the main window's Callsign field and set RX if you know its audio frequency. You can also double-click a decoded message to fill both fields. Enter your own callsign in the My Station section of Settings → General to enable the focused search. With only the target callsign, DX can still listen for related messages and learn the target's frequency.

Compare with WSJT-X

Compare receives live decoded messages from WSJT-X and merges them with ft8.rs's local results. It shows which messages were received by one program and which were received by both.

  1. Use the same receive audio. Set ft8.rs and WSJT-X to listen to the same receiver, frequency and audio channel, and start reception in both.
  2. Check ft8.rs's listener. In Settings → Compare, enable Listen to UDP. It is enabled by default on first use, with Host 127.0.0.1 and Port 2237.
  3. Set WSJT-X's UDP output. Send WSJT-X's UDP reports to 127.0.0.1, port 2237. This assumes both programs run on the same computer. If the port is in use, select the same free port in both programs.
  4. Wait for new receive slots. The message list uses source colors, with a legend in Compare settings: only WSJT-X, only ft8.rs, or both decoders. Comparison uses new live reports; it does not import WSJT-X's message history.

Match ± Hz sets the allowed audio-frequency difference when matching messages received by the two programs. The default is ±7 Hz.

Compare combines reception results from WSJT-X and ft8.rs in one display. To send local results to other programs, enable UDP reports in Settings → Output.

Command line

Linux

Open a terminal in the extracted directory. List the input devices, then start listening with the appropriate device number.

./ft8rs-cli monitor
./ft8rs-cli monitor --device 0

Windows PowerShell

In the extracted directory, run .\ft8rs-cli.exe monitor --device 0 in PowerShell. Replace 0 with your input device number.

The command-line tool also decodes WAV recordings. See the full user guide for more audio settings, recording playback and UDP options.
