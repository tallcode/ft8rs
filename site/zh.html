这是什么

FT8 是业余无线电中用于弱信号通信的一种数字模式。它以 15 秒为一个收发时隙，通过简短、结构化的消息交换呼号、网格位置、信号报告和通联确认，适合在信号较弱时进行基本信息交流。它不是语音模式，也不是用来长篇聊天的。更多背景可阅读 WSJT-X 官方用户指南。

ft8.rs 是一款 FT8 解码软件。将电台或 SDR 的接收音频送入电脑，就可以查看收到的呼号、信号强度和消息。

它只接收，不带发射功能。你可以用它收听频段活动，也可以针对一个呼号持续监听。软件提供 WSJT-X、JTDX、Hybrid 和 DX 四种解码模式。

如果你同时使用 WSJT-X，还可以通过 Compare 在同一张消息列表中对照两个软件的接收结果。

开始使用

以下步骤适用于 Windows 图形界面。

  1. 连接音频。将电台或 SDR 调到要收听的 FT8 频率，通过声卡、USB 音频或虚拟音频线把接收音频送入电脑。保持电脑系统时间准确。
  2. 打开软件。完整解压下载的 ZIP 文件，运行 ft8rs-gui.exe。
  3. 选择输入。在 Settings → Audio 中选择接收机对应的输入设备和声道，确认有音频电平。如果只有一侧声道有信号，就选择对应的 Left 或 Right。
  4. 选择模式。初次使用可以保留默认的 WSJT-X。在 Settings → Decode 中可以切换其他模式。
  5. 开始收听。点击主窗口的播放按钮。软件按 15 秒一轮接收 FT8，完成一轮接收后会陆续显示消息；点击停止按钮结束收听。

什么时候填写自己的呼号

普通频段收听可以留空，没有自己的呼号也能使用。在 Settings → Station 中，My Callsign 填写自己的呼号，My Grid 填写自己的网格位置；它们与主窗口中目标电台的 Callsign / Grid 是分开的。

  • 关注涉及自己呼号的消息时：填写正确的 My Callsign，可以为解码器提供已知呼号线索，辅助部分弱信号和压缩呼号的识别；消息列表也会突出显示自己的呼号。这不是所有信号都会更容易解码的增益开关。
  • 使用 DX 关注一个目标时：主窗口的目标 Callsign 是必填项，自己的呼号仍可留空。如果同时提供有效且不同的本站呼号和目标呼号，软件可启用额外的呼号对上下文恢复，尝试补充与这对呼号有关的消息。

这些字段只提供接收和解码上下文。填写呼号不会启用发射功能，ft8.rs 始终只接收。

怎样选择解码模式

在 Settings → Decode → Profile 中选择模式，也可以使用 Profile 菜单。

WSJT-X
默认模式，使用 WSJT-X 的 FT8 解码方式，适合开始收听和一般频段监听。
JTDX
使用 JTDX 的 FT8 解码方式。同一段音频可能与 WSJT-X 解出不同的消息，可尝试对照，也可以调整 SWL 和 Deep decode 选项。
Hybrid
同时运行 WSJT-X 和两路 JTDX 解码，再合并结果、去除重复消息。两路 JTDX 分别使用原始音频和自动增益调整后的音频。适合希望综合不同解码方式的用户，会使用更多计算资源；还可以开启下方的 SIC 和实验解码功能尝试补充结果。
DX
针对一个目标呼号持续监听，显示与目标有关的消息。先在主窗口的 Callsign 中填入目标呼号，再开始收听；双击已解码的消息也可以选中目标并设置接收音频频率。DX 会自行管理 SWL 和深度搜索，不需要再调整它们的通用开关。

Hybrid 的解码选项

选择 Hybrid 后，在 Settings → Decode 中可以调整以下选项。可以先保留默认设置，再逐项开启，观察同一音频输入下的结果和电脑负载。

Cross cancellation（SIC，交叉抵消）
默认开启。利用已经解出的信号，在音频副本中将它抵消后再搜索，尝试找出被重叠信号遮住的消息。由这一步补充的消息在行末标为 sic。关闭后，WSJT-X 和两路 JTDX 的基础解码仍然保留。
SWL（收听搜索）
默认关闭。启用 JTDX 面向收听的搜索方式，在 Hybrid 中同时作用于两路 JTDX。它会改变搜索过程，可能增加耗时；开启后的结果不一定包含关闭时的所有消息。
Deep decode（深度搜索）
默认关闭。启用 JTDX 围绕所选接收音频频率的进一步搜索，适合关注某个信号时尝试。可以双击消息设置目标和频率；额外搜索可能增加处理时间。
Experimental decoder（实验解码，exp）
默认关闭，仅在 Hybrid 中可用。开启后加入 ft8.rs 自研的补充解码，尝试恢复稳定弱信号，以及受单音干扰或其他 FT8 信号遮挡的消息。新增结果在行末标为 exp，基础结果仍先显示。它会增加计算量，补充结果可能晚几秒出现；本轮解码的后台处理可能持续约 10 秒或更久。它不能覆盖所有衰落、漂移或干扰情况，也不保证每一轮都增加消息。

sic、exp 等后缀表示消息的解码来源，不是消息正文，也不是“已确认正确”的标记。重要呼号或罕见信号，仍需结合后续时隙和实际接收情况核对。

Compare：与 WSJT-X 对照

Compare 接收 WSJT-X 发来的实时解码消息，与 ft8.rs 的本地结果合并显示。你可以直观看到哪些消息只有一个软件收到，哪些消息两者都收到。

  1. 使用相同的接收音频。让 ft8.rs 和 WSJT-X 监听同一接收机、同一频率和同一音频声道，并同时开始接收。
  2. 检查 ft8.rs 的接收设置。在 Settings → Compare 中勾选 Listen to WSJT-X (UDP)。首次使用默认已开启，Host 为 127.0.0.1，Port 为 2237。
  3. 设置 WSJT-X 的 UDP 输出。将 WSJT-X 的 UDP 报告发送地址设为 127.0.0.1、端口设为 2237。这里假设两个软件在同一台电脑上；如果端口已被其他软件占用，两边一起改用一个空闲端口。
  4. 等待新的接收时隙。消息列表会按来源显示不同颜色，图例可在 Compare 设置页查看：仅 WSJT-X、仅 ft8.rs、两者都有。它对照的是新收到的实时消息，不会导入 WSJT-X 的历史列表。

Match ± Hz 是频率匹配容差，默认为 ±7 Hz。同一时隙、消息内容匹配且音频频率差在容差内时，会合并为“两者都有”；SNR 或 DT 数值不必完全相同。调整容差只影响之后收到的消息。

Compare 只用于显示对照，不会把 WSJT-X 的消息送回 ft8.rs 帮助解码，颜色也不代表消息一定正确。Settings → Output 则是把 ft8.rs 的结果发送给其他软件，默认端口为 2238，与这里的接收设置是两个功能。

没有收到消息？

先检查接收频率、电脑时间和音频输入。在 Settings → Audio 查看电平，确认选中的是接收机音频，且输入没有过载。如果电平一直没有变化，请检查设备、声道和系统的音频输入权限。

Linux 命令行

在解压目录打开终端，先列出输入设备，再用对应的设备编号开始收听：

./ft8rs monitor
./ft8rs monitor --device 0

命令行也支持解码 WAV 录音。更多音频设置、录音解码和 UDP 使用方法见 完整使用说明（英文）。
