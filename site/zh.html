这是什么

ft8.rs 是一款基于 WSJT-X 和 JTDX 的 FT8 解码软件，以 Rust 重新实现，并加入了自研的实验性解码功能。

开发者可使用独立的 Rust FT8 解码库 ft8rs；ft8.rs 应用基于该库构建。

它只接收，不带发射功能。你可以用它收听频段活动，也可以针对一个呼号持续监听。软件提供 WSJT-X、WSJT-X+、JTDX、Hybrid 和 DX 五种解码方案。

如果你同时使用 WSJT-X，还可以通过“对比”功能在同一张消息列表中对照两个软件的接收结果。

FT8 是业余无线电中用于弱信号通信的一种数字模式。它以 15 秒为一个收发时隙，通过简短、结构化的消息交换呼号、网格位置、信号报告和通联确认，适合在信号较弱时进行基本信息交流。它不是语音模式，也不是用来长篇聊天的。更多背景可阅读 WSJT-X 官方用户指南。

开始使用

以下步骤适用于 Windows 图形界面，菜单和设置项名称以中文版为准。可在 设置 → 通用 → 语言 中选择 中文；英文界面对应 Settings → General → Language。

  1. 连接音频。将电台或 SDR 调到要收听的 FT8 频率，通过声卡、USB 音频或虚拟音频线把接收音频送入电脑。保持电脑系统时间准确。
  2. 打开软件。完整解压下载的 ZIP 文件，运行 ft8rs.exe。
  3. 选择输入。在 设置 → 音频 中选择接收机对应的输入设备和声道，确认输入电平有变化。如果只有一侧声道有信号，就选择对应的 左声道 或 右声道。
  4. 选择解码方案。初次使用可以保留默认的 WSJT-X。在 设置 → 解码 → 解码方案 中可以切换其他方案。
  5. 开始收听。点击主窗口的播放按钮（开始监听）。软件按 15 秒一轮接收 FT8，完成一轮接收后会陆续显示消息；点击停止按钮（停止监听）结束收听。

我的呼号与网格

普通频段收听可以留空，没有自己的呼号也能使用。在 设置 → 电台 中，我的呼号 填写自己的呼号，我的网格 填写自己的网格位置；它们与主窗口中目标电台的 呼号和网格 是分开的。

正确填写我的呼号，有助于解码包含你呼号的部分弱信号消息，以及还原消息中以哈希形式编码的该呼号。对于不包含该呼号的消息，这项设置不提供直接的解码帮助。消息列表也会突出显示你的呼号。

填写呼号不会启用发射功能，ft8.rs 始终只接收。

解码方案

在 设置 → 解码 → 解码方案 中选择方案，也可以使用 解码方案 菜单。

WSJT-X
默认方案，使用 WSJT-X 的 FT8 解码方式，适合开始收听和一般频段监听。
WSJT-X+
先显示 WSJT-X 的基础解码结果，再自动运行兼容恢复和候选重试。兼容恢复（Pc）补搜旧编码的 RR73 和部分在候选筛选时漏掉的 CQ；候选重试（Pr）为部分弱信号或重叠信号尝试不同的时间和频率对齐。
JTDX
使用 JTDX 的 FT8 解码方式。同一段音频可能与 WSJT-X 解出不同的消息。
  • SWL（收听搜索）默认关闭，可在设置 → 解码中开启。在 Hybrid 中同时作用于两路 JTDX。开启后可能耗时更长，也可能漏掉关闭时能解出的部分消息。
Hybrid
同时运行一路 WSJT-X+ 和两路 JTDX 解码，再合并结果、去除重复消息。两路 JTDX 分别使用原始音频和自动增益调整后的音频。这种组合会使用更多计算资源。Hybrid 会自动执行交叉抵消（SIC）：在音频副本中抵消已解出的信号，再搜索可能被它遮住的消息。
  • 实验解码器：默认关闭。在设置 → 解码中开启后，即可使用评测中的 Hybrid + exp 档，尝试恢复稳定弱信号以及受单音干扰或其他 FT8 信号遮挡的消息。基础结果先显示，补充结果可能晚几秒出现；本轮后台处理可能持续约 10 秒或更久。
DX
要在目标电台的 RX 音频频率附近深搜，请使用 DX。在主窗口的呼号中填写目标呼号，已知音频频率时填入 RX。也可以双击已解码的消息，一次填入呼号和频率。要启用定向深搜，请在设置 → 电台中填写我的呼号。只填写目标呼号也可以监听相关消息，DX 会在接收过程中学习目标频率。

对比：与 WSJT-X 对照

“对比”功能接收 WSJT-X 发来的实时解码消息，与 ft8.rs 的本地结果合并显示。你可以直观看到哪些消息只有一个软件收到，哪些消息两者都收到。

  1. 使用相同的接收音频。让 ft8.rs 和 WSJT-X 监听同一接收机、同一频率和同一音频声道，并同时开始接收。
  2. 检查 ft8.rs 的接收设置。在 设置 → 对比 中勾选 监听 WSJT-X（UDP）。首次使用默认已开启，主机为 127.0.0.1，端口为 2237。
  3. 设置 WSJT-X 的 UDP 输出。将 WSJT-X 的 UDP 报告发送地址设为 127.0.0.1、端口设为 2237。这里假设两个软件在同一台电脑上；端口被占用时，两边改用同一空闲端口。
  4. 等待新的接收时隙。消息列表会按来源显示不同颜色，图例可在对比设置页查看：仅 WSJT-X、仅 ft8.rs、两者均解出。它对照的是新收到的实时消息，不会导入 WSJT-X 的历史列表。

匹配容差（± Hz）用于匹配两个软件收到的消息，允许的音频频率差默认为 ±7 Hz。

对比用于合并显示 WSJT-X 与 ft8.rs 的接收结果；设置 → 输出中的UDP 上报用于将本地结果发送给其他软件。

人工数据测试（合成音频）

用下方五种解码配置重放同一批 144 组 FT8 音频，测试稳定弱信号和几种干扰条件。每组音频的目标消息、频率和时间均已知。

测试音频由 FT8 消息波形（参照 WSJT-X 的 gen_ft8wave.f90 实现生成）与人工生成的噪声、持续单音或重叠信号混合而成；每条路径都处理同一份 15 秒音频，并按预先知道的消息、频率和时间核对结果。另外 48 组没有目标消息的控制音频用于检查误解码，未计入图表。在这 192 组测试中，各模式均未观察到错误消息。

这是一组有意挑选的实验条件。日常接收中，弱信号往往会同时受到变化的衰落、漂移和干扰影响，很少有这样稳定、可控的信号。因此，图中的提升不能推算为实际使用时的解码率，也不保证每一轮都能多收到消息。

Linux 命令行

在解压目录打开终端，先列出输入设备，再用对应的设备编号开始收听：

./ft8rs-cli monitor
./ft8rs-cli monitor --device 0

命令行也支持解码 WAV 录音。更多音频设置、录音解码和 UDP 使用方法见 完整使用说明（英文）。
