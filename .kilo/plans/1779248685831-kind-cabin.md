# 流式 FT8 解码器 (Stream Decoder)

## 目标

- 新建 `stream` 分支（基于 `dev`）
- 实现一个完全照搬 WSJT-X 架构的流式解码组件
- **短解码**：灵敏度 20/20，性能 <2s（保持现有水平）
- **流式长解码**：音频流播放完成后 **15秒内** 完成全部解码，灵敏度 **400/449**
- 底层实现可与短解码完全分离，两个场景独立优化

## 架构分析

### WSJT-X 流式解码架构 (`ft8_decode.f90`)

WSJT-X 从声卡实时接收音频，核心流程：

1. **音频累积**：`nzhsym` 标记当前累积的符号数（41=11s, 47=13s, 50=15s）
2. **Stage 1 (nzhsym=41)**：前 11s 数据，`syncmin=2.0`，只检强信号
3. **Stage 2 (nzhsym=47)**：减去已检信号（`subtractft8` + `lrefinedt`），清理残差
4. **Stage 3 (nzhsym=50)**：完整 15s 残差解码，`syncmin=1.3`，多 pass
5. **AP 解码 (ft8_a7d)**：利用前一时隙解码结果（`ndec_early` 数组），在已知频率/DT 附近强制解码
6. **跨时隙记忆**：`ndec(jseq,0)` 保存上一时隙的 (dt, freq, msg)，用于下一时隙 AP

关键设计：
- 每个 `ft8b` 调用使用**局部栈变量**（`bmeta`, `bmetb`, `s8`, `cd0` 等），无共享状态
- `HashCallBook` 仅在 **unpack 后**写入，不在候选解码循环内读写
- AP 解码（`ft8_a7d`）是**独立阶段**，在所有 `ft8b` 候选处理完后执行
- `ndec_early` 数组存储 (freq, dt, msg, itone) 用于段内减法，不依赖全局 book

### 当前 ft8rs 架构问题

| 问题 | 原因 |
|------|------|
| 传入 `HashCallBook` 后性能暴跌 10x | `decode.rs:285` 的 `book.is_some()` 门控禁用 `par_iter` |
| 段间共享 book 强制串行 | `DecodeWorkspace` 和 `coarse_downsample_cache` 是 `&mut`，无法跨线程共享 |
| AP 与主解码耦合 | `try_decode_passes` 内集成 AP，但缺少 WSJT-X 的 `ft8_a7d` 独立 AP 阶段 |
| 缺少跨时隙记忆 | 没有类似 `ndec(jseq,0)` 的机制保存上一时隙结果 |

### Phase 2: 音频缓冲管理 (`buffer.rs`)

**设计目标：** 模拟 WSJT-X 的 `nzhsym` 累积机制

```rust
pub struct AudioBuffer {
    samples: Vec<f64>,          // 累积的音频样本
    sample_rate: u32,
    nzhsym: usize,              // 当前累积符号数 (41, 47, 50)
}

impl AudioBuffer {
    /// 推入新音频块（如 0.5s 一块）
    pub fn push(&mut self, chunk: &[f32]);
    
    /// 检查是否达到解码阶段
    pub fn stage(&self) -> DecodeStage; // Early(41), Subtract(47), Full(50)
    
    /// 获取当前阶段对应的数据窗口
    pub fn data_for_stage(&self, stage: DecodeStage) -> &[f64];
}

pub enum DecodeStage {
    Early,    // nzhsym=41, ~11s
    Subtract, // nzhsym=47, ~13s
    Full,     // nzhsym=50, 15s
}
```

### Phase 3: 跨时隙记忆 (`cross_slot.rs`)

**设计目标：** 等价于 WSJT-X `ndec(jseq,0)` 和 `ndec_early`

```rust
pub struct CrossSlotMemory {
    // 当前时隙解码结果（nzhsym<50 时累积）
    early_decodes: Vec<SavedDecode>,
    // 上一时隙解码结果（用于 AP）
    previous_slot: Vec<SavedDecode>,
}

pub struct SavedDecode {
    pub freq: f64,
    pub dt: f64,
    pub msg: String,
    pub itone: [i32; 79],
    pub snr: f64,
    pub subtracted: bool,
}

impl CrossSlotMemory {
    /// 保存新解码结果
    pub fn save(&mut self, decode: SavedDecode);
    
    /// 获取需要减法的信号（nzhsym=47 阶段）
    pub fn get_unsubtracted(&self) -> Vec<&SavedDecode>;

    pub fn get_previous_slot(&self) -> &[SavedDecode];
    
    /// 时隙切换：当前 → 上一时隙
```

### Phase 7: 核心 StreamDecoder (`decoder.rs`)

**设计目标：** 整合所有组件，实现 WSJT-X 风格的流式解码

```rust
pub struct StreamDecoder {
    buffer: AudioBuffer,
    memory: CrossSlotMemory,
    config: StreamDecodeConfig,
    decoded: Vec<DecodedMessage>,
}

impl StreamDecoder {
    /// 推入音频块
    pub fn push_audio(&mut self, chunk: &[f32]);
    
    /// 检查并执行解码（根据 buffer.stage()）
    pub fn process(&mut self) -> Vec<DecodedMessage>;
    
    /// 时隙结束，返回所有解码结果
    pub fn finish_slot(&mut self) -> Vec<DecodedMessage>;
}
```

**处理流程（等价于 `ft8_decode.f90:decode`）：**

```
1. nzhsym=41 (Early):
   - sync8(dd, syncmin=2.0) → 强信号候选
   - ft8b_stream(parallel) → 解码强信号
   - 保存到 CrossSlotMemory.early_decodes

2. nzhsym=47 (Subtract):
   - 对 early_decodes 中未减法的信号执行 subtract_signal(lrefinedt=true)
   - 残差更新

3. nzhsym=50 (Full):
   - sync8(residual, syncmin=1.3) → 全部候选
   - ft8b_stream(parallel) → 解码所有候选
   - 合并结果

4. AP 阶段 (ft8_a7d):
   - 对 previous_slot 中的信号，在已知 freq/dt 附近强制解码
   - 合并 AP 结果

5. finish_slot:
   - rotate_slot() → 当前 → 上一时隙
   - 返回所有解码结果
```

## 关键设计决策

1. **不共享 HashCallBook 到候选循环** — 这是性能退化的根因。AP 在独立阶段处理。
2. **每个 ft8b 局部状态** — 匹配 WSJT-X 栈变量设计，天然线程安全。
3. **预计算只读缓存** — `coarse_downsample_cache` 改为预计算，候选只读访问。
4. **跨时隙记忆独立于 AP book** — `CrossSlotMemory` 存储 (freq,dt,msg,itone)，不依赖 hash 表。
5. **短解码与流式解码完全分离** — 两个场景独立优化，互不影响。
