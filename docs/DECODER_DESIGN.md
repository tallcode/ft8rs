# 解码方案定位与功能划分

本文件定义 ft8rs 库中各解码路径及 ft8.rs 应用解码方案的长期职责，
用于新功能立项、实现归属和验收。2026-11-12 梳理现有边界；本次只调整
文档，不改变运行行为、默认值、公开入口、GUI 名称或协议标识。
各实现文档中的历史测量保留原条件与结论，本文件不扩大其证据范围。

## 方案关系与产品责任

| 路径或方案 | 定位 | 主要责任 |
|---|---|---|
| WSJT-X / JTDX | 上游对齐基准 | 保留各自可追溯、可比较的原版接收行为 |
| WSJT-X+ | 沿 WSJT-X 接收链路持续增强的完整解码器 | 独立承担日常接收，改进自身搜索、解调、恢复和计算效率 |
| Hybrid | 多解码路径的组合方案 | 组合 Plus、JTDX/noAGC、JTDX/AGC，管理去重、协作、预算与回调 |
| Hybrid + exp | Hybrid 加自研专项接收能力 | 通过独立接收方法，在声明场景中补充基础路径的盲区 |
| DX | 面向目标的接收编排 | 利用目标上下文选择既有观察与隔离恢复任务；不作为新增 DSP 的默认归属 |

Hybrid 已包含 WSJT-X+ 主路；Hybrid + exp 是启用可选分支的 Hybrid 配置，
不是与 Plus 平级、互相替代的独立解码器。Plus 的改进可经主路惠及两档
Hybrid，但不同方案的配置、预算和协作机会不保证任意输入下的严格包含关系。

exp 的算法由 `decode/experiment/` 独立维护，只由 Hybrid 调用，
没有独立 profile、可执行文件或公开解码入口。它可复用未经修改的原版
协议/FEC 函数及现有 Plus FEC，但不因此归属 Plus 或取得独立确认资格。

实现说明：[Plus](../crates/ft8rs-core/src/decode/lib_wsjtx_plus/README.md)、
[Hybrid](../crates/ft8rs-core/HYBRID.md)、
[exp](../crates/ft8rs-core/src/decode/experiment/README.md)、
[DX](../crates/ft8rs-core/DX.md)。

## 功能归属规则

优先按接收链路的所有权、依赖和长期责任划分，再单独判断成熟度。

1. **增强 Plus 自身接收链路，归 Plus。** 功能使用或延伸 Plus 的候选、
   解调、FEC、历史或恢复流程，并可由独立 Plus 方案验收。允许使用
   隔离会话、音频副本和追加回调保护基础行为；实现为支路不改变归属。
2. **组合既有接收能力，归 Hybrid 编排。** 包括分支选择、去重、来源记录、
   相减种子选择、调用已有相减与重解能力、预算和回调调度。算法内部的
   候选调度仍由相应接收器维护。
3. **增加独立自研接收方法，归 exp。** 它可拥有自己的候选发现、
   信道假设、软信息、波形判定和残差搜索，通过完整组合下的增量收益验收。
   不要求单独覆盖完整解码器的所有场景。
4. **通用计算复用单独论证。** FFT、工作区或 FEC 优化按实际调用方和
   等价性证据决定归属；不要仅因多个路径调用就移动到共享层，更不能
   借共享优化改变受保护的原版行为。

“输出需要合并”“做了相减”“使用 AP”“计算昂贵”“尚不成熟”都不能单独
决定归属。Plus 中的专项恢复可以合理存在；exp 也可以改善常见 AWGN
弱信号。通用场景与特殊场景只是选题倾向，不是模块边界。

Hybrid 原版路径与 DX 不得为增强功能修改 `lib_wsjtx/`、`lib_jtdx/`
的源码、阈值、候选顺序、AP 调度或数学计算，也不得复制后修改来绕开
这一限制。Plus 的独立演进不构成修改受保护原版路径的授权。

## 现有功能归属

以下功能保留现有归属，不因本次文档梳理迁移实现。

| 已有功能 | 归属 | 依据 |
|---|---|---|
| Plus FFT、计算复用、BP/OSD 实现优化 | Plus | 改善自身计算链路 |
| 时间/频率细化、候选重试 | Plus | 延伸自身搜索 |
| 旧 RR73/CQ 兼容、弱 CQ 与历史重复码字恢复 | Plus | 利用自身候选、模板和历史；专项性质不要求迁往 exp |
| 三路解码、输出账本、有限跨解码器相减重解 | Hybrid / 公共编排 | 组合既有能力 |
| 独立前端、软度量、波形拟合、干扰线处理、残差发现 | exp | 独立接收模型与判定方法 |
| 脉冲恢复、频漂恢复、Gaussian-channel / 快衰落相关解调 | exp | 当前与自研接收器和准入方法结合；能力范围以各项证据为准 |
| 自研接收器中的受限显式 AP 假设 | exp | AP 属于该接收方法，结果仍按 exp 隔离 |

测试专用的新接收器原型仍是研究；有源码或通过某项研究测试，不代表
已经加入生产调度或具备可对用户声明的能力。

## 重叠规划的责任拆分

Plus 早期计划中的“信道/干扰感知软信息”“更准确 SIC”“FEC 扩搜”等是
研究主题，不能整体视为 Plus 对所有相关算法的所有权。后续按下表拆分，
不按算法名称分配，也不把同一项收益重复记给多个方案。

| 研究主题 | Plus 路线 | exp 路线 | Hybrid 编排责任 |
|---|---|---|---|
| 同步与候选覆盖 | 改善 Plus 候选、多时间峰、时频细化与原音频/残差搜索覆盖 | 独立前端、候选发现与替代同步方法 | 分配预算与交付结果；不实现新的同步算法 |
| 软信息与信道模型 | 改善 Plus 现有解调流程的噪声/干扰估计、可靠度及信道细化 | 独立相干、Gaussian-channel、衰落或频漂接收方法及其判定 | 提供不可变输入和显式上下文，保持状态隔离 |
| SIC / 重叠信号恢复 | 改善 Plus 自身相减器及自身残差搜索 | 自研信道拟合、条件波形判定、信号分离和专项残差恢复 | 验证/选择跨路径种子，调用既有相减及解码函数，控制轮次 |
| FEC / AP | 优化 Plus BP/OSD，研究自身有限扩搜、可靠度假设和 AP/历史恢复 | 为自研软信息使用受限 FEC/AP 假设并独立验收准入；复用 FEC 不等于修改原版 | 选择合法上下文与任务；不将派生输出制造成独立证据 |
| 性能与并行 | 优化 Plus 热点、内存、SIMD 和内部候选执行 | 优化自研前端、度量、拟合及内部搜索 | 管理路径并发、总预算、输出顺序和消息回调 |
| 专用后端/设备 | 有 Plus 热点与端到端证据时单独立项 | 有自研接收器热点与收益证据时单独立项 | 管理资源与截止时间；不预设硬件加速必然有收益 |

同一算法可有不同接入方案。例如频漂补偿接回 Plus 候选细化时属于 Plus；
使用独立接收模型并作为补充输出时属于 exp。先明确一种接入方式和
主责模块，另一种作为独立候选方案比较，避免无归属的重复建设。

## 成熟度与接入

成熟度按每项能力记录，独立于模块归属；不要求新增用户开关或状态枚举。

| 状态 | 应有说明 | 接入含义 |
|---|---|---|
| 研究原型 | 假设、接入意图、诊断结果和未解决问题 | 保留在研究工具或测试中，不因位于 exp 就自动进入运行路径 |
| 有范围证据的能力 | 声明场景、已知真值增益、错误/未确认输出、保留结果与资源测量 | 完成适用本机验证后才可接入相应路径；保留证据限制 |
| 经持续验证的能力 | 更广录音、信道、负例、配置和目标硬件证据，以及长期回归 | 可继续留在原模块；成熟不自动改变默认值或开放公开入口 |

exp 的开关与 `exp` 日志后缀描述分支来源，不代替各项能力的成熟度说明。
现有 GUI **Experimental decoder**、`--hybrid-experiment` 和默认关闭行为保留。
对外说明应列出有证据支持的适用场景、资源代价和限制，不承诺统一 dB
收益，不把所有子能力描述为同一验证程度。

exp 自身允许专项覆盖不全，但必须报告既有 exp 能力的覆盖变化。
成熟后的合理去向包括：继续作为专项分支；将已独立验证的通用改进
提取到 Plus；在证据充分时另行评估整体架构。迁移到 Plus 必须证明
独立 Plus 中的收益、旧输出保留、错误和资源表现，不能仅凭 Hybrid 中
有增益。当前 Hybrid-only 和无公开入口的边界继续成立。

## 新任务与验收口径

每项新任务先记录以下内容；研究阶段未知项应明确列为待验证。

- **问题与范围：** 哪类信号的哪个盲区；依赖候选、音频、历史和上下文是什么。
- **归属与接入：** Plus、exp 或编排；预期调用位置、输出来源、可变状态与音频隔离。
- **比较基线：** Plus 自身改进对比关闭该改进的 Plus；exp 首次接入对比
  Hybrid，后续新增能力对比关闭该能力的当前完整 Hybrid + exp。
  编排改进对比相同路径与配置下的旧编排。组合还需验证既有基础输出保留。
- **结果证据：** 逐槽/逐条新增正确、错误、未确认、基础丢失和既有专项覆盖变化。
  新增不能抵消旧消息丢失；未经标注的录音新增不能计为已确认收益。
- **资源与时效：** 相同录音、配置、CallDB、构建及硬件；串行测量，分别记录
  消息回调和全部任务完成，检查剩余预算竞争、最坏槽及下一槽排队。
- **成熟度与接入结论：** 当前证据支持什么、尚不能支持什么，以及正式回归入口。

接入产品的 exp 不降低适用的正确性要求。新增错误率按
`新增错误 / (新增正确 + 新增错误)` 单独统计，未确认输出另列且不计入
已判定分母，同时保留基础错误；继承适用方案的验收门槛，不用总体正确率稀释
新增分支问题。Plus 已有的新增错误率和时间要求继续有效；软预算不代表
硬截止，有限零错误样本不证明通用错误率达标。

基础输出、可变会话和音频保持隔离；恢复结果不回灌原版 AP/呼号记忆，
不作为新的独立确认。未知来源保持未知，标记不进入消息正文或 UDP 消息。
本机解码验证使用优化构建；消息显示通常以下一时隙 +2/+3 秒评估，
不得为等待全部后台任务而延迟已有消息。详细要求见
[开发与解码审查](DEVELOPMENT.md#decoder-change-review)和[验证记录](VALIDATION.md)。
