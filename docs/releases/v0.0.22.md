# ft8rs v0.0.22

This release brings the native-alignment, cooperative-decoder, audio/GUI and
reference-test changes since v0.0.21 into one receive-only FT8 release.

## Decoder changes

- Align native WSJT-X/JTDX noise/input scaling, AP state, contest tables and
  staged audio snapshots with their original sources. WAV and live input share
  anti-alias conversion.
- Run Hybrid as three independent paths: WSJT-X, JTDX/noAGC and JTDX/AGC, with
  payload-aware hash-display deduplication and bounded isolated cancellation.
- Add controlled three-way DX target observation/recovery while retaining the
  protected native tasks, private sessions and target-state boundaries.
- Default to one logical JTDX partition; explicit zero selects CPU-dependent
  automatic partitioning. SWL controls both JTDX paths in Hybrid.
- Restore native packing/unpacking edge cases, reserved call-token behavior and
  zero-metric normalization. Restore the strict 21/21 WSJT-X short-recording gate.

## Audio and GUI

- Correct Mono capture: request a native mono stream, or use channel 1 when only
  a multichannel stream is available. Mixing is an explicit option.
- Expose the active capture format, input/channel peaks and slot diagnostics.
- Keep GUI controls responsive during decoding, reconcile failed device changes,
  validate settings and improve external WSJT-X UDP comparison.
- Stabilize settings-page layout/device menus and use centered SVG play/stop
  controls across font sizes and display scales.

## Tests and documentation

- Add fixed native FT8 coding/hash/waveform references, original test28 cases,
  Watterson channel fixtures and degraded historical recordings.
- Share audio regressions across WSJT-X, JTDX, Hybrid and DX. Preserve 1458
  individual reference-target observations across 24 degraded-recording cases.
- Keep generation/capture/comparison scripts for explicit candidate updates;
  daily tests reuse stored data without a Fortran dependency.
- Reorganize the README, usage/build guides, calibration conditions, test/data
  update workflow and dated Hybrid/DX experiment reports.

## Validation and limits

Local validation completed before release:

- 205 core release tests passed, including all ignored gates.
- 217 workspace fast unit tests passed, including a post-sync rerun.
- All eight historical recording control reports remained byte-identical.
- 64/64 known-message Watterson replays recovered correctly; 48 trials require
  recovery and 16 disturbed-channel trials remain diagnostic.
- Formatting, strict workspace/all-target Clippy, fixture checks and documentation
  link/example checks passed.

WSJT-X targets remain 21/21 short and 424/424 long. JTDX remains 20/20 short and
430/431 long at the fixed four-partition/2022-CallDB operating point. The known
long-recording miss remains `140700 F1MLZ UA3QNA -04`.

Unlabelled real-recording outputs are not confirmed gains. Nominal noise addition
is relative to mixed-audio power, not a per-station dB sensitivity measurement.
JTDX's geographic filter remains a deliberate partial port. Native calls already
running cannot be forcibly cancelled; callback latency and worker completion are
separate. Windows DAX hardware comparison remains a separate live check.

## Packages

All packages use RustFFT at the native 3840-point sync size and have no FFTW
runtime dependency:

- `ft8rs-windows-x86_64.zip`: Windows GUI and CLI; x86-64-v3 CPU required.
- `ft8rs-linux-x86_64.tar.gz`: Linux CLI; x86-64-v3 CPU required.
- `ft8rs-macos-arm64.zip`: locally built Apple Silicon GUI app and CLI. The app
  is unsigned; macOS may require permission to open it and access audio input.

Keep the bundled `ALLCALL7.TXT` beside the binaries. The macOS app also includes
its own copy. The historical `ALLCALL7.TXT.2022` is for test calibration and is
not the shipped runtime database. Checksums are supplied in `SHA256SUMS.txt`.
